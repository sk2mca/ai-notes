Important AI Concepts:
Level: beginner  ·  Common scenario: company HR assistant  ·  Goal: see how each concept differs using the same simple, real-world setting
1 · LLM
Large Language Model
An AI model that understands and generates text and can perform reasoning-like tasks

Example

User
“What is paid leave?”

What happens

  1. Input — the user asks a question.
  2. Process — the LLM interprets the question and generates a response.
  3. Output — “Paid leave is time off from work for which an employee continues to receive pay.”
RememberLLM = Understand and generate.
2 · TOOL
Tool / Skill
A capability an AI application can invoke to perform a specific action or retrieve information

Example

User
“How many paid leave days do I have left?”

What happens

  1. Request — the LLM determines that it needs the employee's leave balance.
  2. Tool call — it requests the get_leave_balance() tool.
  3. Execution — the tool queries the HR system and returns 8 days.
  4. Response — the LLM replies, “You have 8 paid leave days remaining.”
RememberTool = Do a specific task.
3 · MCP
Model Context Protocol
A standard protocol that lets AI applications connect to external tools, data, and services

Example

User
“Check my remaining leave balance.”

What happens

  1. Connection — the AI application connects to an HR MCP server.
  2. Discovery — the server exposes an available tool, such as get_leave_balance.
  3. Request — the AI application invokes that tool through MCP.
  4. Result — the HR service returns the leave balance, which the AI can use to answer.
ImportantMCP doesn't calculate the leave balance itself. The underlying tool or service performs the actual work.
RememberMCP = A standard way to connect AI applications to tools and data.
4 · RAG
Retrieval-Augmented Generation
Retrieve relevant external information and give it to an LLM to produce a grounded answer

Example

User
“According to our company policy, how many paid leave days can employees carry forward?”

What happens

  1. Question — the user asks about company policy.
  2. Retrieval — the system searches company documents for the carry-forward policy.
  3. Context — it retrieves a relevant passage, such as “Employees may carry forward up to 5 unused days.”
  4. Generation — the LLM uses that passage to formulate an answer.
  5. Response — “According to the retrieved policy, employees may carry forward up to 5 unused days.”
ImportantRAG does not automatically guarantee a correct answer. The quality of retrieval and the source documents matters.
RAG is an idea, not a product. You can build it with plain Python or with LangChain — see the next card.
RememberRAG = Retrieve relevant information, then generate an answer.
5 · CHAIN
LangChain
A framework for building LLM applications by connecting models, prompts, tools, retrievers, and other components

Example

Developer goal
“Build a chatbot that answers questions from our HR policy PDFs.”

This is a RAG application. The pipeline is the same either way; the only choice is who writes the glue code — you, or LangChain's ready-made components.

The same pipeline, built two ways

1 · Load the PDFs
Without LangChain: write or integrate your own PDF-reading code.
With LangChain: use a document loader.
2 · Split into chunks
Without LangChain: implement your own chunking logic.
With LangChain: use a text splitter.
3 · Generate embeddings
Without LangChain: call an embedding model directly.
With LangChain: use an embedding integration.
4 · Store in a vector database
Without LangChain: set up and call the vector database client yourself.
With LangChain: use a vector store integration.
5 · Retrieve relevant text
Without LangChain: implement the vector search yourself.
With LangChain: use a retriever.
6 · Send context + question to the LLM
Without LangChain: write the prompt and the model call.
With LangChain: use a retrieval chain, or compose the components yourself.

Option 1 — without LangChain (manual Python)

# Steps 1-2: load and split
from pypdf import PdfReader
text = "".join(p.extract_text() for p in PdfReader("hr_policy.pdf").pages)
chunks = [text[i:i + 800] for i in range(0, len(text), 700)]

# Steps 3-4: embed and store (a plain array here; use a vector DB in production)
import numpy as np
from openai import OpenAI
client = OpenAI()

def embed(texts):
    r = client.embeddings.create(model="text-embedding-3-small", input=texts)
    return np.array([d.embedding for d in r.data])

vectors = embed(chunks)

# Step 5: retrieve
def retrieve(question, k=3):
    scores = vectors @ embed([question])[0]
    return [chunks[i] for i in scores.argsort()[::-1][:k]]

# Step 6: ask the LLM
question = "How many leave days can I carry forward?"
context = "\n\n".join(retrieve(question))
reply = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": f"Answer using only this context:\n{context}\n\nQuestion: {question}"}],
)
print(reply.choices[0].message.content)

Option 2 — with LangChain

from langchain_community.document_loaders import PyPDFLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_community.vectorstores import FAISS

docs = PyPDFLoader("hr_policy.pdf").load()
chunks = RecursiveCharacterTextSplitter(chunk_size=800, chunk_overlap=100).split_documents(docs)
store = FAISS.from_documents(chunks, OpenAIEmbeddings())
retriever = store.as_retriever(search_kwargs={"k": 3})

question = "How many leave days can I carry forward?"
context = "\n\n".join(d.page_content for d in retriever.invoke(question))
llm = ChatOpenAI(model="gpt-4o-mini")
print(llm.invoke(f"Answer using only this context:\n{context}\n\nQuestion: {question}").content)
Both sketches are illustrative; library versions and import paths change over time. Notice that the steps are identical — LangChain only replaces the glue code you would otherwise write.

Which should you choose?

  • Without LangChain — more control over every step, fewer framework dependencies. Best when you want to understand each step or need direct control.
  • With LangChain — often faster to assemble a standard RAG pipeline, with less integration code. The cost is extra framework abstractions to learn and maintain.
ImportantLangChain is a framework, not an LLM model itself. It makes integration easier; it doesn't make RAG mandatory or guarantee better answers. You still choose the embedding model, vector store, retrieval strategy, and LLM.
RememberLangChain = Build an LLM application by connecting components.
6 · GRAPH
LangGraph
A framework for building stateful workflows with steps, conditional branches, and repeated execution

Example

User
“I need leave approval. Please check my balance and submit my request if I am eligible.”

What happens

  1. Start — the workflow receives the leave request.
  2. Check — a node calls the HR system to check the leave balance.
  3. Branch — a conditional edge routes the workflow based on eligibility.
  4. Act — if eligible, the workflow can request confirmation and submit the application.
  5. Finish — the workflow returns the submission status or explains why it could not proceed.

Workflow graph

START ─▶ [check_balance] ─▶ eligible?
                              │
              yes ────────────┼──────────── no
               ▼                              ▼
     [ask_confirmation]               [explain_why_not]
               ▼                              │
       [submit_request]                       │
               ▼                              ▼
              END ◀───────────────────────────┘

State carried along: employee, balance, eligible, confirmation, status
ImportantLangGraph doesn't automatically make a workflow an agent. It can run either a fixed workflow or an agent-style loop.
RememberLangGraph = Manage the workflow, state, and decisions between steps.
7 · AGENT
Agent
An AI system that uses an LLM to choose actions, invoke tools, observe results, and repeat as needed

Example

User
“Find out whether I can take leave next Monday and submit my request if I can.”

What happens

  1. Think — the agent identifies that it needs the leave policy, leave balance, and possibly the leave calendar.
  2. Act — it calls the relevant tools to retrieve that information.
  3. Observe — it checks the returned results.
  4. Decide — it determines whether another check is needed or whether the task can proceed.
  5. Act again — if eligible, it may ask the user for confirmation before submitting the request.
  6. Finish — it reports whether the request was submitted or explains what prevented submission.
ImportantThe agent should not assume a request is approved just because it is eligible to submit. Actual approval may require a manager or another system.
RememberAgent = Decide what to do, use tools, check results, and repeat until done or stopped.
FLOW
Fixed Flow vs. Dynamic Flow
Who decides the next step: the developer, or the agent?

A. Fixed flow — no agent required

You already know which data sources must be checked for each request. The developer defines the steps in advance and the application simply executes them.

User
“Verify order 12345 against the database and refund policy, then email the result.”
User question
      │
      ▼
Predefined workflow
      │
      ├──▶ Database ──▶ Fetch order
      │
      ├──▶ RAG ───────▶ Retrieve refund policy
      │
      ▼
Verify ──▶ Email result

The agent is not required: the application checks both sources because the developer defined those steps in advance.

B. Dynamic flow — an agent can be useful

You don't know in advance which data sources will be needed. The next action depends on what the system discovers along the way.

User
“Investigate order 12345 and determine why it failed.”
User question
      │
      ▼
Agent decides: "Which source should I check first?"
      │
      ▼
Tool: query order database ──▶ finds a payment mismatch
      │
      ▼
Agent decides again: "A payment lookup is needed to investigate further."
      │
      ├──▶ Payment API
      │
      ├──▶ RAG (only if policy is relevant)
      │
      ▼
Agent evaluates findings ──▶ explains likely cause

The agent chooses the next useful action based on the results. It may call additional tools, stop when it has enough evidence, or ask the user for missing information.

RememberFixed flow = developer chooses the steps. Dynamic agent flow = the model chooses actions as results come back.
SUMMARY
Quick Comparison
One-line memory aid for all seven concepts
  • LLM: Understands and generates language.
  • Tool: Performs a specific action or retrieves data.
  • MCP: Standardizes how AI applications connect to tools and data.
  • RAG: Retrieves relevant information to ground an answer.
  • LangChain: Helps connect the components of an LLM application.
  • LangGraph: Orchestrates stateful workflows and branching.
  • Agent: Chooses and executes actions dynamically, using feedback from tools.
These concepts can work together. For example, an agent may use an LLM, call tools exposed through MCP, retrieve policy documents using RAG, and run its workflow with LangGraph. LangChain may help integrate some of those components.
